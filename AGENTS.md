# AGENTS.md

tetanus is a self-hosted disk and ZFS monitor for home NAS hosts: SMART health, disk lifecycle and inventory, ZFS topology, and a diary of what happened to each disk. A dumb collector on each host ships raw command output to one server, which does all parsing. Single user, no UI auth, one unprivileged Docker container; collectors authenticate with a shared enrol token.

Read `docs/001-Product-goals.md` for the vision, `docs/003-Architecture-and-data-model.md` for the design and `docs/004-Project-plan.md` for the build order before feature or design work.

## Stack

Nuxt 4 (Vue, Nuxt UI 4, Tailwind 4) with a Nitro server, Drizzle ORM on better-sqlite3, zod, Biome for lint/format, Vitest for tests, lefthook for the pre-commit hook. Node 24 + pnpm 10.

- `app/` — Nuxt frontend (layout, pages, components, composables)
- `server/` — Nitro API routes, task queue, SSE
  - `database/` — Drizzle schema, column helpers, generated SQL migrations, client, migrator
  - `services/` — domain logic over the DB
  - `tasks/` — the task queue (`queue.ts`, `handler.ts`) and queueable tasks registered in `router.ts`
  - `utils/` — `ServiceError` and route helpers
- `shared/` — code shared by app and server; `shared/app.ts` holds `APP_NAME`, the only place the project name appears; zod schemas in `shared/schemas/`
- `test/` — test setup, DB flush helper, e2e dev-server harness (`test/api/`)
- `docs/` — working docs managed by `wj`

## Commands

- `pnpm test` — Vitest (unit project with a per-file `:memory:` database, then e2e route tests that boot `nuxt dev`)
- `pnpm lint` — Biome (writes fixes); `pnpm lint:ci` to check only
- `pnpm typecheck`
- `pnpm db:migrate` — apply migrations (not automatic in dev; the Nitro plugin migrates at boot in production)
- `pnpm exec drizzle-kit generate --name <snake_case_name>` — generate a migration after editing `server/database/schema.ts`
- `pnpm dev` — dev server on :3000; do not run it yourself, the user should have one running already

## Conventions

- British English in naming, copy and communication.
- Prefer self-documenting code over comments.
- Biome formats and lints everything; `docs/`, `bin/` and `test/fixtures/` are excluded. Fixtures are captured output: never reformat them.
- `app/` and `shared/` must not import from `server/` (Biome `noRestrictedImports`); move what both need to `shared/`.
- Tests are co-located as `*.test.ts` next to the code; route tests are `test/api/*.e2e.test.ts`.
- Zod schemas for request bodies live in `shared/schemas/`; routes validate with `readValidatedBody(event, schema.parse)`.
- Services are plain functions over `db`. They throw `ServiceError` (`server/utils/serviceError.ts`) for expected failures; routes surface them with `respondWithServiceErrors`.
- Tables are PascalCase; use the column helpers in `server/database/columns.ts`. Migrations are generated by drizzle-kit and hand-named.
- The container never runs host commands; data arrives through the ingest seam described in `docs/003-Architecture-and-data-model.md`.
